# Generator settings reference

Use [config.yaml](config.yaml) to control the simulation and [events_config.yaml](events_config.yaml) to insert events. After editing either file, rerun both commands in the [generator guide](README.md#generate-a-separate-sample).

## General settings

| Field | Meaning |
|---|---|
| `years` | Length of the simulation. |
| `start_date` | First date, for example `"2024/01/01"`. |
| `revenue_per_conv` | Revenue assigned to each conversion, shared by all channels. |
| `customer_types` | Groups used to split daily sales, such as `New` and `Returning`. |
| `sales_channels` | Sales outlets, such as `Ecom` and `Stores`. |

The sales split is created by Python. The current implementation supports at most four customer-type × sales-channel combinations; the default is two of each.

## Baseline sales and daily spend

`baseline` controls sales before advertising contributions:

| Field | Meaning |
|---|---|
| `daily_mean` | Typical daily baseline sales. |
| `trend_p` | Simulator trend setting. |
| `temp_var` | Simulator temporal-variation setting. |
| `temp_coef_mean`, `temp_coef_sd` | Mean and spread of temporal coefficients. |
| `error_std` | Size of random baseline noise. |

These settings are passed to siMMMulator. `daily_mean`, both temporal coefficients, and `error_std` are multiplied by the country's `market_size`.

`campaign_spend.daily_total_mean` and `campaign_spend.daily_total_std` set the mean and spread of the daily advertising budget before allocation to channels. Both are also scaled by `market_size`.

## Countries

```yaml
countries:
  - code: DE
    name: Germany
    market_size: 1.0
```

`code` identifies the market in media data and event settings. `name` appears in sales data. `market_size` scales baseline sales and spend; a value of 0.5 makes the market half the reference size.

## Channels

Each entry in `channels` has these fields:

| Field | Meaning |
|---|---|
| `name` | Channel name used in data and event settings. |
| `type` | `impression` or `click`: which measurement the simulator generates. |
| `platform` | Output platform label, such as `Google Ads`. |
| `true_cvr` | Conversion rate per impression or per click, depending on `type`. |
| `true_cpm` | Cost per 1,000 impressions; used for impression channels. |
| `true_cpc` | Cost per click; used for click channels. |
| `mean_noisy_cpm_cpc`, `std_noisy_cpm_cpc` | Mean and spread of noise added to media cost. |
| `mean_noisy_cvr`, `std_noisy_cvr` | Mean and spread of noise added to conversion rate. |
| `decay` | How much ad effect carries over. Higher values mean a longer lasting effect. |
| `alpha_saturation`, `gamma_saturation` | Shape of the saturation curve, which controls how response changes as advertising increases. |
| `spend_share_min`, `spend_share_max` | Bounds on the channel's share of daily spend. |
| `assumed_ctr` | Click-through rate used by Python to fill the media measurement not generated by R. |

The scripts order impression channels first and click channels second. The last channel **after this reordering** gets the remaining budget, so its share bounds are unused. Keep the other channels' maximum shares below 1 in total to leave a positive remainder.

For impression channels, Python estimates clicks using `assumed_ctr`; for click channels, it estimates impressions. This does not change simulated spend or sales. The estimated column is not independent evidence that a spend change was real.

## Insert an event

Example: turn off all German advertising for 55 days.

```yaml
- pattern_id: DE_DARK_01
  pattern_type: dark_period
  country: DE
  channel: ALL
  start_day: 175
  end_day: 230
  multiplier: 0
  description: All German advertising pauses for 55 days.
```

| Field | Meaning |
|---|---|
| `pattern_id` | Unique label for the event entry. |
| `pattern_type` | Label describing the intended pattern. |
| `country` | A country `code` from the main config. |
| `channel` | A configured channel name, or `ALL`. |
| `start_day` | First affected day, counting from zero. |
| `end_day` | First day after the affected window. |
| `multiplier` | Spend factor: 0 means off; 3 means triple spend. |
| `description` | A readable explanation for the answer file. |

`single_channel` keeps the named channel active and turns off the others. Other patterns multiply the targeted channel's spend, or every channel when `channel: ALL`. Use separate entries for each off-window in a pulse train. A late launch is an initial off-window followed by normal activity.

Day offsets use an **exclusive end**: `start_day: 0`, `end_day: 7` changes the first seven days. With a January 1 start, that means January 1–7 inclusive. The detector's last affected date is `start_date + end_day - 1`.

Use the YAML offsets or benchmark `scenario.json` when checking exact boundaries. The legacy `ground_truth.csv` end-date column uses a different convention and is clamped at the end of the dataset.

## Notes for changing the scripts

The R generator uses one-day campaigns (`frequency_of_campaigns = 1`), so a campaign ID maps directly to a day. Changing campaign frequency also requires changing event injection to use the right dates.

When adding numeric settings to the R script, use `as.numeric()` before passing them to siMMMulator. YAML can read whole numbers as integers, while the simulator expects doubles.
